## 実API

`npm run test:workflows:live --prefix plugins/sokomade`が7シナリオすべて成功しました。設定済みGoogle/OpenAI APIと公開報告ソースを使い、相談はテスト終了時に破棄しています。公共の施設だけで検証し、個人の住所・実際の物件候補は使っていません。

1. SFで候補を追加せず報告レイヤーを取得。初期範囲内に1033の公開位置グループ。網羅性は未確認のpartial。
2. 実AIへ「SFを見せて。表示範囲の公開報告について」と相談。出発地なし、経路なしで地図命令と報告を取得。匿名化交差点・対象期間・被害確率ではないことを説明。
3. 「この辺でカフェを2軒探して」。出発地を要求せず、2店舗を取得。経路は取得しない。
4. 公開施設の検証地点A/Bから検証勤務先へ通勤比較。Googleの住所候補を確認した座標をテスト入力として明示。2組の往復と条件内代替を取得。Aの1912秒は条件外、Bの1628秒は30分以内と、実AIが説明。
5. 「比較は残したまま、スーパーを2軒探して」。3地点・経路ID・往復30分条件を保持したまま追加検索。
6. 渋谷へ移動し、地図の点を周辺分析。逆ジオコーディングした町丁目「渋谷区渋谷2丁目」に対応。2026年1〜9月累計、対象3種別77件。町丁目の値であり沿道件数ではなく、geometryはnull。
7. ロンドンの公開テスト地点へ移動。同じ相談を保ち、報告レイヤーはunsupported。安全扱い・架空件数にしない。

SFの取得期間は2026-07-19以上、2026-10-17未満（SF現地日付）。値は取得時点の検証結果であり、将来の検索結果・所要時間を保証しません。住所検索が複数候補になるケースも確認し、アプリは黙って1件を採用しません。
