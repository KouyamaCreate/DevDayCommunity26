# CITY LIGHT — 渋谷 治安度2.5Dマップ

渋谷駅（35.658034, 139.701636）から**直線半径1km**の建物を、施設構成に基づく環境参考スコアの明るさで探索するローカルWebアプリです。

- Navara / Three.js / WebAssemblyによる実際の建物ポリゴンの2.5D表示
- OpenPOIの施設19,687件、国土地理院の建物形状7,069件を保存
- 施設のある3,297建物をOpenAI Decisions APIで時間帯を指定せず評価
- 建物・施設・住所検索、支援施設・スコアでの絞り込み、真上／斜め表示の切替
- 建物クリックで施設候補、3軸の評価内訳、対応付け方法、出典、評価リクエストIDを確認
- 全施設・形状・評価結果・ライセンスをJSONで書き出し

公開デモ：[CITY LIGHT](https://shibuya-light-map.zhuanyonggithub.chatgpt.site/)

## 起動

Node.js 22.22以上（検証環境：22.22.3）。このフォルダで初回のみ `npm ci`。

```sh
npm run dev
```

ブラウザで <http://127.0.0.1:4317> を開きます。保存済みの実評価はAPIキーなしで表示できます。追加の評価にはAPIキーをサーバー側に設定します。

キーをファイルに残さない場合：

```sh
npm run dev -- --credential-stdin
```

`Ready for API credential on hidden stdin.` と表示されたらキーを入力してEnter。入力は端末に表示しません。キーはサーバープロセスのメモリにのみ保持し、再起動時に消えます。画面・ログ・評価JSONには含めません。

環境変数を利用する場合は `.env.example` を参考に `.env` に `OPENAI_API_KEY` を設定できます。`.env` はGit除外済みです。APIキーをソースや公開データに含めないでください。

画面の「評価について」から「未評価の建物を一括評価」を選択するか、起動中のサーバーに対して別端末で `npm run evaluate` を実行します。取得済みの同一入力の評価は再利用し、未評価分だけ実行します。処理中は画面上部に進捗を表示。レート制限時は待機・再試行します。

```sh
npm test
npm run build:local
npm start
```

`npm start` はビルド済みアプリを同じURLで起動します。評価APIを使用する場合は `.env` または `npm start -- --credential-stdin` を使います。外部には公開せず、127.0.0.1のみにバインドします。

## データ更新

```sh
python3 scripts/fetch-data.py
node scripts/fetch-buildings.mjs
npm run data:prepare
npm test
npm run build
```

- `data/pois.json`：OpenPOIから取得した施設とレコード単位の出典・ライセンス
- `data/geography.json`：地理院ベクトルタイルから抽出した建物・道路・鉄道
- `data/buildings.json`：施設を空間的に対応付けた建物
- `data/unassigned.json`：建物に割り当てられない施設
- `data/evaluations.json`：Decisions APIの実評価。モデル・日時・入力ハッシュ・APIリクエストIDを保持
- `public/data/map.json`：地図表示向けの軽量データ

サーバーは起動時にデータを読むため、更新後は再起動してください。評価は入力ハッシュが一致するものだけ読み込みます。

## 評価方法

元プロトタイプの `shibuya-environment-v1` の評価軸と重みを `server/decisions.mjs` に引き継いでいます。実行時に別プロジェクトへの依存はありません。最終版のルーブリックは `shibuya-environment-v2` とし、元実装の時間帯条件を除きました。

| 評価軸 | 重み | 施設データから評価する内容 |
|---|---:|---|
| 人の目 visibility | 40% | 日常的な来訪を支える用途 |
| 支援施設 support | 20% | 医療・薬局・公共窓口等の手掛かり |
| 落ち着き calmness | 40% | 混雑・騒音に関する手掛かり |

各0〜4の連続スコアを25倍して100点換算し、加重平均します。複数建物を1リクエストにまとめ、各質問で対象の建物キーを指定。建物ごとに1つのスコアを評価します。時間帯は指定せず、営業時間や現地照明を推測しません。**地図の明るさは治安度スコアを表し、実際の昼夜や照明を表しません。**未評価を0点として扱いません。

明るさは黄緑（HSLの色相82°・彩度48%）に統一し、`L = 5 + 90 × (score / 100)^1.7` で低スコアを暗く、高スコアを明るく表示します。建物本体の自己発光は0。`src/uniform-glow.ts` は建物形状のマスクのみを読み、スコア・本体色・自己発光バッファを参照せずに、一定の色・強度・半径でグローを合成します。光のにじみは建物本体の外側だけに加え、本体の明暗差を保ちます。未評価の本体は暗いグレーです。選択は白い輪郭のみで、スコアの明るさを変えません。高さは9・18・30mの模式表示です。

## 対応付けと制約

OpenPOIは最大200件の矩形検索を再分割し372回取得しました。末端1区画が上限に到達しており網羅的ではありません。半径1km内のデータのみ残し、完全一致の施設名＋座標を重複排除しています。座標違い・表記違いの重複は残る可能性があります。

施設座標を内包する最小面積の建物を優先し、外側は12m以内の最寄りポリゴンを候補にします。18,673施設を3,297形状に対応付け、1,014施設は未割当。座標内包も入居先の確定ではありません。施設名や建物名は住所由来の候補で、住所・入居現況・現地状況を未検証。地理院タイルの境界で建物が分割される場合があります。

スコアは施設構成に基づく実験的な環境参考評価で、犯罪発生率や安全保証ではありません。犯罪統計・現地照明・営業時間・警備・防犯設備は含みません。業種だけから犯罪や違法行為を推定しません。モデルのconfidenceは現実の安全性の確率ではありません。

## 静的共有版（ChatGPT Sites等）

`npm run build` は取得済みの3,297建物の実評価・施設詳細・検索索引・JSON書き出しを含む共有版を作成します。`npm run build:local` は再評価APIを使えるローカル版です。共有版はAPIキーやローカルサーバーに依存せず、地図・検索・絞り込み・建物詳細を利用できます。新しい評価はローカルで取得して再公開してください。このPRには既存Sitesの識別子・デプロイ設定を含めていません。生成した `dist/` は静的サイトとして配信できます。

## 描画形状の整形

`scripts/prepare-render.mjs` は表示用形状だけを整形します。同じタイル境界付近の重複や交差面を差分処理で除き、隣接する壁は表示上10cm内側に寄せます。全建物の黒い輪郭線を外し、面と線の深度競合を避けています。元の建物形状・施設の対応付け・Decisions評価は変えていません。7,069レコードのうち完全に重なる206形状は重複描画せず、6,863形状を表示。932形状の重なりを処理し、結果は `data/render-verification.json` に保存しています。

道路と鉄道は地表にクランプして描画し、建物の屋根を貫通する常時前面の線表示を避けています。

## カメラ操作と配色

注視点は渋谷駅から半径1,100m（対象範囲1km＋100mの余白）、地表までの視線距離は200〜3,200m、俯角は30〜90度に制限。ドラッグ／タッチのカメラ変更もフレームごとに制約し、空や範囲外へ向かう操作を補正します。慣性は移動・回転80ms、ホイールは入力の単位と大きさを正規化し、1イベントの倍率変化を約0.84〜1.20倍に抑えます。ズーム・北向き・傾きボタンは現在の注視点と倍率を保ち、ホームボタンで初期視点へ戻します。

背景とUIは[参照PR #2](https://github.com/my-name-is-yu/DevDayCommunity26/pull/2)の白、淡いグレー（`#f1f4f5`）、紺（`#102455`）、青（`#0969f5`）、罫線（`#dce5f2`）に合わせています。建物本体の黄緑とスコアによる明暗差、一定強度のグローは維持しています。

## 未評価建物の地域統計による補完

警視庁の[2025年・町丁別、罪種別及び手口別認知件数（年計）](https://www.keishicho.metro.tokyo.lg.jp/about_mpd/jokyo_tokei/jokyo/ninchikensu.html)と、[CODHの2020年国勢調査町丁・字等別境界データ](https://geoshape.ex.nii.ac.jp/ka/)を利用。最新の通年データを比較に使い、2026年月累計と混在させません。原本、取得日時、SHA-256、利用条件は `data/open-data/`、加工後の町丁目形状・件数・建物との対応付けは `public/data/area-context.json` に保存しています。

- 実際の境界とのポリゴン交差で、元の建物形状の80%以上を含む町丁目にだけ割り当てます。住所の近似・最近傍町丁目・町丁目中心からの補間は使いません。
- 町丁目**全体**の総認知件数を町丁目**全体**の面積（km²）で割ります。地図の1km円で切った面積は分母に使いません。渋谷区・港区・目黒区の名前を厳密照合できた284町丁目を母集団とし、同順位を平均順位にした密度順位（最小0）から `round(80 - 60 × rank / (N - 1))` で20〜80に変換。全罪種を総件数で扱い、独自の重大度の重みは加えません。欠測を0件とみなしません。
- **独自の地域参考指数**であり、警視庁が作った治安スコアではありません。建物自体の犯罪件数・被害確率・安全性を示しません。人口・昼間人口・来訪者数の差は補正できていません。国勢調査境界は住居表示の境界と一致しない場合があります。
- 3,297棟のDecisions API施設評価を優先。施設情報のない3,772棟のうち3,770棟を地域参考値で補完し、2棟は境界が曖昧なためグレーのままです。元の施設・評価キャッシュは変えていません。同じ町丁目の補完建物には同じ値を表示します。
- 一覧の「地域参考」、詳細の出典・町丁目全体の件数・罪種内訳で施設評価と区別し、凡例のチェックで補完をオフにできます。JSON書き出しにも統計と対応付けを含めます。APIキーを使わず再現できます。

再取得は `npm run crime:fetch`、保存済み原本からの再計算は `npm run crime:prepare`。通常ビルドも保存済み原本から再計算し、ビルド時に外部データへアクセスしません。
